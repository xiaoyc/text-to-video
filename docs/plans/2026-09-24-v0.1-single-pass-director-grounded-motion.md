# Text-to-Video v0.1 — Single-pass Director + Grounded Motion Plan

Date: 2026-09-24

## 1. Product goal

Build a clean narrative-to-video engine around one principle:

> The LLM makes creative decisions once; deterministic code validates, compiles, grounds generated assets, resolves camera motion, previews, and renders.

The v0.1 golden path is:

```text
Script
  -> Director LLM (normally 1 call)
  -> DirectorPackage
  -> Local validators
  -> optional Director repair (max 1 call)
  -> deterministic image-prompt compilation
  -> image generation/import
  -> one Vision review that also returns subject grounding
  -> grounded motion resolution
  -> shot preview
  -> local asset/motion retry
  -> lock
  -> real TTS + retime
  -> HyperFrames / Three.js render
```

Normal pre-edit target: **1 text-model call**.  
Failure-repair target: **at most 2 text-model calls**.

## 2. Explicit non-goals for v0.1

Do not port legacy orchestration from `video-factory`.

Not in the v0.1 core:

- WeMM / Qdrant / TV-library retrieval.
- Jianying draft generation.
- Multiple narrative/attention/bible/shot agents.
- LLM prompt writer.
- Independent Hook LLM reviewer by default.
- Repeated hook/camera/visual replan loops.
- Full 3D reconstruction.
- SAM/depth/segmentation as a hard dependency.
- Micro-video generation.
- A production TTS provider.

Those can be added later behind source/provider interfaces.

## 3. Six architectural layers

### 3.1 DIRECT

Input: script + style/aspect-ratio constraints.

Output: one `DirectorPackage` containing:

- narrative beats;
- attention/hook strategy;
- project bible;
- TTS hints;
- shots;
- each shot's subject and intent;
- asset strategy/state;
- creative motion intent;
- optional spatial template intent.

The Director describes **what should be perceived**, not exact generated-image coordinates.

### 3.2 VALIDATE

Deterministic validators inspect the candidate package together:

- schema/identity integrity;
- hook/reveal leakage;
- camera-rhythm repetition;
- visual-idle risk;
- asset-state contradictions;
- spatial-template requirements;
- required subject / framing contracts.

All blocking findings are consolidated into one `DirectorFinding[]`.

If any blocking finding exists, call the Director repair path **once** with only the necessary context. Revalidate once. Remaining blocking findings fail closed.

### 3.3 ASSET

Image prompts are compiled from structured intent, not rewritten by another LLM.

Inputs:

- ProjectBible;
- ShotSubject;
- ShotIntent;
- AssetState;
- character/look references;
- prompt template;
- aspect ratio.

Output: `AssetRequest[]`.

Changing the prompt compiler must not invalidate the Director plan.

### 3.4 GROUND

After a real image exists, one Vision pass performs both:

1. acceptance review;
2. subject grounding.

Minimum v0.1 grounding:

- primary subject detected;
- normalized bounding box;
- normalized center;
- confidence;
- recommended focus center;
- safe maximum crop scale.

Do not pretend to know exact image coordinates before generation.

### 3.5 RESOLVE

Camera motion is two-stage:

```text
CreativeMotionIntent
  + actual AssetGrounding
  -> ResolvedMotion
```

Example:

```text
Director: slow push-in toward the copper coins
Vision: coins center=(0.28,0.64), bbox=..., maxScale=1.55
Resolver: pan slightly toward the coins, then zoom, settle without cropping them
```

If the asset cannot satisfy the shot intent:

1. adapt motion within the creative contract;
2. reduce zoom / combine pan + zoom;
3. if still incompatible, reject the asset and regenerate/reselect it.

### 3.6 RENDER

Preview is a first-class quality gate.

A shot can be previewed independently without rerunning Director or regenerating unrelated assets.

Later production render sequence:

```text
locked DirectorPackage
  -> real TTS
  -> timing alignment / retime
  -> grounded resolved motions
  -> HyperFrames / Three.js
  -> final video
```

## 4. Core domain model

### DirectorPackage

```ts
interface DirectorPackage {
  version: 1
  narrative: { beats: NarrativeBeat[] }
  attention: AttentionPlan
  bible: ProjectBible
  ttsHints: TtsBeatHint[]
  shots: DirectorShot[]
}
```

### ShotSubject

Every shot must declare one primary subject.

Supported subject types:

- `character`
- `object`
- `landmark`
- `relationship`
- `space`

```ts
interface ShotSubject {
  primary: SubjectRef
  secondary: SubjectRef[]
  mustKeepVisible: string[]
  mayLeaveFrame: string[]
}
```

### ShotIntent

```ts
interface ShotIntent {
  narrativeGoal: string
  cameraTask: string
  startFraming: string
  endFraming: string
  subjectDominance: 'low' | 'medium' | 'high'
  preferredPlacement?: Placement
}
```

### CreativeMotionIntent

The Director chooses intent, not pixels:

```ts
interface CreativeMotionIntent {
  type: 'static' | 'push-in' | 'pull-out' | 'pan-left' | 'pan-right' | 'tracking' | 'arc' | 'crane-up' | 'crane-down'
  targetSubjectId: string
  intensity: 'subtle' | 'medium' | 'strong'
  motivation: string
  envelope: string
}
```

### AssetGrounding

Coordinates are normalized to `0..1`.

```ts
interface AssetGrounding {
  assetId: string
  shotId: string
  primary: GroundedSubject
  secondary: GroundedSubject[]
  safeCrop: {
    maxScale: number
    recommendedFocusCenter: Point
  }
}
```

## 5. LLM policy

### Default mode

```text
Director call x1
  -> local validation
  -> PASS
```

### Repair mode

```text
Director call x1
  -> local validation
  -> blocking findings
  -> unified repair x1
  -> local validation
```

Hard limit: `maxDirectorRepairs = 1`.

### Deep mode

Optional later feature. It may add one independent creative review, but must never be the default path.

## 6. Cache boundaries

Cache by semantic stage:

- Director package: script + style + director-contract hash.
- Asset request: final shot + relevant bible slice + prompt-compiler hash.
- Image: asset request + references + image provider.
- Vision grounding: image hash + shot subject + grounding-contract hash.
- Resolved motion: grounding + creative motion + viewport/resolver hash.
- Preview: asset hash + resolved motion + overlay/effect contract.

Consequences:

- changing motion resolver does not rerun the LLM;
- changing prompt compiler does not rerun the Director;
- changing one image does not regenerate the rest;
- changing one shot can invalidate only that shot and dependents.

## 7. Golden test

Use one 20–30 second historical fixture with approximately six shots:

1. copper-coin close-up — object grounding + push-in;
2. Zhou Di vs gate guard — relationship composition;
3. money handoff — exact asset state;
4. guard inspecting coins — focus/refraiming;
5. wife reveal — reveal timing;
6. Yangzhou gate/space — landmark/2.5D intent.

Every architectural change must be testable against this fixture.

## 8. v0.1 implementation phases

### Phase 0 — repository foundation

- TypeScript / Node project.
- Domain types.
- deterministic validators.
- deterministic prompt compiler.
- grounding contracts.
- grounded motion resolver.
- unit tests.
- golden fixture.

Exit: `npm test` validates the core without external services.

### Phase 1 — Single-pass Director adapter

- `TextModel` provider interface.
- structured Director prompt/schema.
- one `planDirectorPackage()` call.
- optional `repairDirectorPackage()`.
- stage metrics.

Exit: a script produces a validated `DirectorPackage` with <=2 text-model calls.

### Phase 2 — Asset generation/import + combined Vision review

- `ImageProvider` interface.
- manual image import provider first.
- `VisionProvider` interface.
- combined acceptance + grounding contract.
- asset retry state.

Exit: a real imported/generated image can be accepted/rejected and grounded.

### Phase 3 — Grounded preview

- resolve camera motion from real grounding.
- generate a lightweight shot preview contract.
- shot-only rebuild.
- motion/grounding debug JSON.

Exit: copper-coin shot visibly tracks the real detected coin position.

### Phase 4 — HyperFrames / Three.js

- renderer adapter.
- 2D/Ken Burns first.
- 2.5D layered mode second.
- spatial templates later.

Exit: the six-shot golden fixture renders as a preview sequence.

### Phase 5 — TTS / final timing

- TTS provider interface.
- real durations.
- optional word/phrase alignment.
- retime without redirection.

Exit: locked creative decisions survive final TTS timing.

```json
  "validation": { "blockingFindings": 0, "durationMs": 0 },
  "repair": { "llmCalls": 0 },

  "preview": { "rebuiltShots": [] }
}
```

## 10. Architectural invariants

1. Renderer code must not become a hidden director.
2. No precise image coordinates are authored before the image exists.
3. Every shot has one primary subject.
4. Every non-static subject-targeted motion must name its target subject.
5. Prompt generation is deterministic by default.
6. One Vision call per candidate should both review and ground.
7. Local validators may reject plans but must not silently rewrite creative decisions.
8. Repair is bounded.
9. Preview and local reruns are first-class.
10. Legacy video-factory features enter only through explicit provider/plugin interfaces.

## 11. Immediate implementation target

The first coding milestone after this document is deliberately small:

```text
DirectorPackage domain model
  -> local validation
  -> deterministic asset prompt
  -> mocked/imported grounding
  -> resolved camera motion
  -> golden unit tests
```

This proves the new project's central contract before integrating any external model or renderer.
